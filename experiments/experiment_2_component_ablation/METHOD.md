# 实验2方法

## 研究问题

1. 诊断 Agent、修复 Generator 和迭代 Controller 逐步加入后，最终严格通过率如何变化？
2. Controller 的拒绝、重试和终态控制是否挽回了第一轮未通过的修复？
3. 完整系统是否同时保持原题、避免新增错误并维持局部最小修改？

## 固定变量

四个条件使用相同的21题队列、相同Gold状态、相同严格成功定义和相同历史审核终态。主指标分母始终为21，不因不可修、未确定或失败而删除样本。

## 自变量与四个条件

| 条件 | Evaluator | Generator | 第一轮后继续 | Controller终态/重验 | 输出能力 |
|---|---:|---:|---:|---:|---|
| 无 Agent | 否 | 否 | 否 | 否 | 保留原证明 |
| 仅单个诊断 Agent | 是 | 否 | 否 | 否 | 诊断，不修改证明 |
| 双 Agent（单轮截断） | 是 | 是 | 否 | 截断 | 最多一个历史修复轮次 |
| 双 Agent + Controller | 是 | 是 | 是 | 是 | 拒绝、重试、整篇重验和保守退出 |

“双 Agent 单轮”通过读取完整轨迹的 `repair_rounds` 重构：只有最终修复成功且 `repair_rounds == 1` 的案例计为成功。需要第二轮才成功的案例在该条件下计为失败。它近似回答“第一轮后停止会怎样”，不是重新调用模型得到的独立样本。

## 主指标

```text
最终严格通过率 = 被记录为 repaired 且人工审核接受的证明数 / 21
```

无 Agent 和仅诊断 Agent 都不改变证明，因此它们的最终通过状态等于原证明Gold的严格 `valid` 状态。队列中没有原始 `valid` 证明，故均为0/21。这里的0%不代表诊断 Agent 没有判断能力。

## 补充指标

- 单 Agent诊断：50题证明有效性准确率、错误类型准确率、首错整体准确率、依赖边F1；
- Controller增量：完整系统成功数减去单轮成功数；
- Controller挽回占比：多轮成功数/全部成功数；
- 保守退出数：`not_repaired_irreparable`；
- 人工审核的问题保持、无新增错误、操作最小性；
- 局部操作分布：`insert_before`、`replace`、`delete`。

## 统计方法

报告原始计数、百分比和单比例Wilson 95%区间。由于条件不是独立随机重跑，不进行配对显著性检验，也不将28.6个百分点解释为无偏因果效应。

## 正式实验扩展设计

投稿级版本应冻结同一测试集、模型快照、prompt、temperature、最大调用数和token预算，独立运行以下条件：无Agent/no-op、单Agent直接修复、双Agent无状态Generator–Critic、双Agent+Controller，并加入去结构化证书、去依赖图、去后代失效、去反例协议和单轮限制等纯消融。每个条件至少运行多个随机种子，并对所有声称成功或虚假修复的样本进行盲审。
