# 新协作者 AI 接手提示词（2026-08-18）

以下提示词供新加入项目的同学复制到其 AI 编程会话中。首次使用完整版；后续按任务选择短提示词。AI 必须以仓库当前文件为事实来源，不得把本提示词中的状态描述当成最新事实。

## 提示词 A：首次完整接手（推荐）

```text
你正在加入一个已有版本化成果的研究工程项目：依赖图驱动的双 Agent 自然语言数学证明审计与局部修复 Harness。仓库中的 Git 历史、PROJECT_INDEX.md、ROADMAP.md、里程碑文档、Schema、测试和冻结清单是事实来源；不要仅凭本提示词推断项目状态，也不要从零重构仓库。

项目核心架构：
1. Evaluator 负责证明节点、直接依赖图、局部证明义务、第一处错误、错误证书和反例语义。
2. Repair Generator 只针对 ErrorCertificate 提交最小局部 PatchProposal，无权接受自己的补丁。
3. Controller 是确定性软件，不是第三个数学 Agent；它负责 Schema、版本、后代失效、回滚、重试、预算、缓存和运行账本。
4. 节点修改后，依赖旧版本的全部直接和间接后代必须失效并按拓扑顺序重验。
5. 自然语言接受不等于形式证明；未找到反例不等于命题正确；系统必须允许 undetermined；增加假设不计为原问题修复成功。

当前状态概览（必须阅读仓库后复核）：
- M0–M4 的核心工程契约、50 题 Gold、Evaluator 和反例闭环已有冻结版本，但历史盲态、外部身份和部分冻结摘要存在明确限制。
- M5 已实现 Repair Generator/Controller、补丁审核、版本、事务回滚、后代失效与连续首错修复；交互式材料包含 36 项处置，其中 24 项接受修复、12 项因原命题为假或无定义终止。正式生产 Provider pilot、独立全量补丁复核、真实成本/失败记录仍未完成。
- M6 已实现九方法配置、基线/消融、统一预算、缓存隔离、意向治疗账本、评分和统计 fixture；50×9 的交互式工程账本完成，但共享历史预测，不是九组独立 Provider 实验，不能据此宣称显著优越性。
- M7 的 50 题交互式工程运行已完成，200–500 题正式候选的来源/许可/摘要门已有进展；独立 A/B Gold、必要裁决和 Provider 原始运行证据仍阻塞正式科学结论。
- M8 已有论文/发布门和三方工程审查骨架，但整体未完成，release_allowed 仍应为 false。
- 项目所有者已在当前范围豁免密码学签名并允许 M6/M7 工程执行；该豁免不等于独立身份、盲测、Provider 证据或论文级验收完成。

请按顺序阅读：
1. AGENTS.md
2. README.md
3. PROJECT_INDEX.md
4. ROADMAP.md
5. docs/two_person_work_plan.md
6. docs/project_validation_and_acceptance_plan.md
7. 与当前任务相关的 docs/milestones 文档
8. 相关 harness、schemas、data manifest 和 tests
9. skills/math-proof-repair-agent/SKILL.md（当任务涉及证明义务检查时）

第一次只做只读审计，不修改文件。输出：
1. 你理解的系统数据流和角色边界；
2. M0–M8 状态表，分为“工程已完成、形式/科学门未完成、存在矛盾需复核”；
3. 当前任务涉及的权威文件、代码、Schema、测试和数据清单；
4. 你发现的状态描述冲突、哈希漂移、过时文档或证据缺口；
5. 一个不改变冻结资产的最小下一任务建议；
6. 在行动前需要项目负责人确认的事项。

禁止事项：
- 不修改历史冻结产物来让测试通过；应新增版本或勘误。
- 不把 fixture、交互式投影、人工会话记录说成正式独立模型实验。
- 不生成虚假的签名、独立身份、时间戳、Provider response ID、token、成本或延迟。
- 不删除失败运行，不把 not_applicable/undefined/undetermined 统一写成 0。
- 不擅自改变共享 Schema、Gold 标签、指标定义或研究主张。
- 不把用户授权执行误写成科学验收通过。

完成只读审计后等待具体任务。
```

## 提示词 B：开始具体开发任务

```text
继续本仓库的双 Agent 自然语言证明审计项目。本次任务是：[写明具体目标]。

先定位任务所属里程碑、验收门、权威文档、实现、Schema、测试和冻结资产。检查 Git 状态并保留无关改动。先报告目标、非目标、受影响契约、风险与验证计划，然后再实施。

实现要求：小而可审查；正反测试同时增加；Schema/prompt/Gold 变化必须版本化；不得原地改写冻结资产；失败必须 fail closed；报告实际测试结果，不得把未运行写成通过。

交接格式：结果、修改文件、测试及结果、数据/Schema 影响、数学假设、证据强度、已知限制、仍阻塞的门、建议下一任务。
```

## 提示词 C：只读进度审计

```text
请对仓库做只读里程碑审计。以 PROJECT_INDEX.md、ROADMAP.md、data 下机器清单、docs/milestones、测试和 Git 历史交叉验证，不只复述 README。

逐个列出 M0–M8：已实现代码、已有数据、已运行测试、人工证据、外部证据、正式退出条件、当前真实状态。重点识别“工程完成但科学证据未完成”“交互式运行但非独立 Provider 实验”“用户豁免但未形成论文证据”等边界。列出冲突来源并给出最小修复建议，不修改文件。
```

## 提示词 D：数学/Gold 审查

```text
本次任务涉及数学证明或 Gold 语义。先阅读 skills/math-proof-repair-agent/SKILL.md 以及相关标注指南。建立节点和依赖关系，检查局部证明义务，区分 proof gap、invalid step、false theorem 和 undetermined，定位第一处问题，并给出最小修复建议。

不要因为结论为真就接受错误证明；不要因为没找到反例就接受命题；不要增加隐藏假设；不要用 Repair Generator 自审补丁。任何 Gold 修改必须附裁决记录并创建新版本，不改写冻结版本。
```

## 提示词 E：代码/PR 复核

```text
请审查当前变更，不直接假设作者结论正确。重点检查角色权限、目标/版本绑定、DAG 与后代失效、事务回滚、缓存指纹、预算与重试、失败分母、not_applicable/undefined/undetermined 语义、冻结哈希和是否存在证据越权。

按严重度报告可执行问题，给出精确文件和行号。若没有发现问题，明确说明残余风险与未覆盖测试。不要把已有测试通过当成数学正确性的充分证据。
```

## 提示词 F：日常续接短提示词

```text
继续 why-repair 项目。先读取 AGENTS.md、PROJECT_INDEX.md、ROADMAP.md 和本任务对应的 milestone/Schema/tests；以仓库当前状态为准。保持 Evaluator、Repair Generator、Controller 权限分离，保护冻结资产和 Gold 版本，不夸大 fixture/交互式结果。本次目标：[目标]；验收标准：[标准]。完成后按“结果、文件、测试、契约影响、证据强度、限制、下一步”交接。
```
