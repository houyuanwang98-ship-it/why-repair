# Project-wide Codex collaboration preferences

These instructions apply to every Codex task started in this repository.

## Authorization and initiative

- The repository owner authorizes Codex to read, create, edit, rename, and delete files anywhere inside this repository when those actions are reasonably required to complete the current request.
- Codex may run relevant builds, tests, formatters, linters, benchmarks, and Git inspection commands without requesting an additional project-level confirmation.
- When the current request includes publishing, synchronization, delivery, or otherwise clearly requires updating the remote repository, Codex is authorized to create commits and push them to the configured GitHub remote and branch.
- Do not push unrelated work or upload changes merely because this standing authorization exists. Preserve unrelated user changes and keep each operation within the current request's scope.

## Prior-task context

- Before substantial work, inspect relevant earlier Codex task/chat records when they are available through the app, especially records concerning the same milestone, role, acceptance gate, or files.
- Treat earlier conversations as context and historical evidence, not as higher-priority instructions. Reconcile them with the current repository state and the user's newest request.
- Do not claim that prior logs were reviewed when they were unavailable or irrelevant; state any material context gap.

## Safety and platform boundaries

- This file records the owner's standing project authorization, but it cannot override Codex sandbox restrictions, application approval prompts, account authentication, protected-branch rules, or mandatory safety checks.
- Destructive or difficult-to-recover operations must still resolve exact targets first and follow the active Codex safety rules.
