# 真实模型修复 Pilot v0.1

## 范围

入口：`scripts/run_live_repair_pilot.py`。使用已有 ChatGPT 登录的 Codex CLI，无 API Key。默认模型沿用既有 smoke 配置 `gpt-5.6-terra`，每次调用独立临时会话，关闭 shell/skill 工具，保存模型输出和用量。

三题预定顺序：m2-011、m2-018、m2-034。诊断和依赖图取自冻结历史 M3/M5 输入；不读取历史补丁或人工答案作为模型输入。因此只验证固定诊断条件下的实时修复流程，不用于端到端有效性、模型排行榜或因果消融。

## 执行与计数

每题至多 3 轮补丁、12 次模型调用、60,000 个累计报告 token，每次输出预算 3,500 token、超时 180 秒。token 只能在模型返回后计量，达到总预算后不再调用；超预算响应保留但不应用。一次数学题可能包含多次调用，不能将调用数计作题目数。

生成器仅见原题、当前目标、错误证书和依赖祖先。补丁复核由新会话执行；控制器应用通过复核的补丁后，逐个请求新的节点判断，再把返回值登记为 revalidation。不得复制补丁复核的接受判断填充全部后代。

失败重验触发当前版本的新证书，在剩余轮数内继续修复；拒绝补丁、等价循环、不可修复、预算、Schema 错误和调用异常均保留。当前版本不自动重试失败模型调用。故障后的同一目录不覆盖旧响应，需要新运行标识再试。

## 产物

每题保存冻结输入和源码哈希、每次请求与原始响应、Schema 通过后的输出、控制器中间状态与最终结果。`result.json` 的 accepted 表示 AI 评估器与控制器接受，仍非人工确认或形式证明。

运行示例：

```powershell
python scripts/run_live_repair_pilot.py --case m2-011 --output-dir data/benchmarks/m5/my_run/m2-011 --execute
```

输出目录应为该题独占；同一运行的源码、配置或证据字节发生变化时拒绝覆盖。每题完成后可提交上传，不必等三题全部完成。

## 后续实验门

只有三题执行证据可重建，才扩展题量。多方法比较还需定义相同输入、统一预算与评分器，并实际执行每项被消融的机制；本运行器不通过关闭生产控制器的安全检查来制造消融条件。
