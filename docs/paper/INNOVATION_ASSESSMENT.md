# 当前创新点与证据边界

更新：2026-09-12。当前最值得检验的研究问题是：**自然语言证明被修改后，哪些旧判断还能使用，如何以可控成本重建接受依据？** 我们已有实现与小规模机制观察，尚未证明完整系统性能领先，也未完成足以支持“首次提出”的系统文献综述。

## 与已有工作的关系

| 已有研究 | 已经覆盖的内容 | 我们应当研究的具体差异 |
|---|---|---|
| [Self-Refine（2023）](https://arxiv.org/abs/2303.17651) | 同一模型生成、反馈并迭代修改答案 | 将每份判断绑定到具体证明版本，研究编辑后旧证据何时失效；生成与批评的角色组合本身不构成新颖性 |
| [ProofFlow（ICLR 2026）](https://proceedings.iclr.cc/paper_files/paper/2026/file/5fce5198dbf92d5ff45f74504431e2ff-Paper-Conference.pdf) | 用依赖 DAG 和分步引理保持证明自动形式化的结构，并比较依赖约束及成本 | 聚焦有缺陷的自然语言证明在多轮局部修改中的证据失效与重新接受；不能把构图、依赖限制或图结构节约成本作为单独的首创主张 |
| [APRIL（2026）](https://arxiv.org/abs/2602.02990) | 从 Lean 编译反馈学习证明修复，并生成相应自然语言诊断 | 在缺少形式内核裁决的自然语言环境中，管理诊断、补丁与重验的不确定性；“诊断加修复”已有先例 |

以上对照根据原论文与官方论文页面作定向核查。表中的“差异”是本项目的研究定位，不等于已经证明所有相关工作都没有这些机制。

## 1. 方法贡献候选：版本约束下的证明证据维护

当前实现把节点判断与原文、版本、作用域及依赖上下文绑定。补丁审核通过后，控制器按旧图与新图计算影响范围，使相关旧判断失效，再沿依赖顺序检查；补丁应用、局部检查完成、全文审核通过和外部评分分别记录。

它回答的是一个具体问题：某一步原来被判正确，修改其前提之后，还能否把这个旧判断作为后续证据？例如将 t=5 改成 t=6，原有 t²=25 的接受记录必须失效，即使最终目标可以通过另一个分支独立证明。

已有证据是可执行控制器、版本/作用域与拒绝过期记录的测试，以及受控机制运行。还需要在真实证明、漏边/错边、作用域变化和多轮编辑上验证。依赖图正确、上下文完整等前提未得到保障时，不能把程序契约写成数学正确性保证；更不能声称得到全局最小修复。

## 2. 已观察到的现象：最终评分会掩盖中间误接受

在相同五节点图、相同编辑及相同检查器下，保留过期后代判断的策略对 3/3 个负控制产生局部误接受，依赖重验与全图重验均为 0/3。加入全文审核后，三种策略都拒绝这些负控制。

因此，本组实验若只报告最终得分，会看不到中间接受机制的区别。论文可以将“编辑后中间误接受”“经过全文审核后的误接受”和“严格接受的最终正文”分别测量，检验最终评分是否掩盖了机制失效。这里是 3 个参数化算术家族的开发观察，尚不能声称是普遍的新发现。

## 3. 待扩大验证的取舍：局部重验节省检查，不保证整体更强

同一受控实验中，依赖重验每例检查 2 个节点，全图检查 5 个，检查量减少 60%，实验模型 token 减少约 49.6%。这个数值只适用于该组构造样例，未纳入真实构图和自主寻找补丁的成本。

端到端第二轮的结果是完整系统 10/18 就绪且严格接受，直接重写 18/18；完整系统成本更高。补充回归修复了一个局部审核问题，但两道长题仍耗尽 token。值得研究的是：受影响子图有多大、构图与审核开销有多高、重复编辑多少轮时，增量重验才划算，而非预设复杂流程一定更好。

以上结果与用量边界见 [最新实验报告](../workflow_v2/LATEST_RUN.md)和[机制实验](../workflow_v2/MECHANISM_STRESS.md)。第二轮有中断续跑成本缺失，不应用选中结果的 token 宣称总体成本优势。

## 当前论文定位

建议围绕“自然语言证明修改后的证据失效与重验”写一条主线：定义证据复用条件，固定编辑比较机制，分别测量中间与最终接受，再测自然证明上的成本和覆盖率。

可以把版本约束、失效和重新接受协议列为系统贡献，将最终评分掩盖中间错误列为待扩大验证的机制发现。24+24 并行调度、换模型、输出 Schema、独立审核或工程测试数量属于实现与复现支持，不宜列作论文核心创新。

正式主张仍需要真实人工校准、新测试集、图质量扰动、配对重复和预算比较。现阶段适合写“实现并观察到”，不适合写“首次”“普遍降低错误率”或“优于现有方法”。
