# M2 Pilot 50 题样本完整修改建议

## 1. 文档目的

本文汇总当前 `pilot_50.jsonl` 的质量判断与全部修改建议，用于提升这批样本对模型自检、第一处错误定位、错误分类、反例发现、局部修复、依赖图恢复和 `undetermined` 校准的检验能力。

建议不要直接覆盖当前 `m2-source-0.1`。当前版本及 Person A、Person B 的原始独立标注应永久保留；修改后的数据应发布为 `m2-source-0.2`，并提供样本迁移记录。

## 2. 当前样本总体评价

当前 50 题适合作为 M2 pilot 和工程冒烟测试，能够判断系统是否具备基础证明审计能力，但暂时不足以支持强模型比较或论文级普遍性结论。

- 工程原型和冒烟测试质量：8/10；
- 模型能力诊断质量：6.5/10；
- 论文级 benchmark 质量：4/10。

### 2.1 主要优点

1. 覆盖完整正确、正确但有缺口、实际无效三种核心状态。
2. 包含“定理为真但证明错误”的关键压力测试。
3. 覆盖代数操作错误、错误推广、定理误用和缺失假设。
4. 多数样本的第一处错误位置明确，便于人工复核。
5. 部分错误定理具有简单、可执行、可独立核验的反例。
6. 证明较短，适合优先调通 Schema、Controller、评测器和 A/B 标注流程。

### 2.2 主要不足

1. 难度整体偏低，强模型可能很快达到饱和。
2. 部分错误带有明显语言提示，模型可能依靠模式匹配而非数学审计。
3. 多数证明只有 2–3 步，依赖图通常只是线性链。
4. 真正需要多步桥接的 gap 样本不足。
5. 代数操作错误和错误推广占比偏高，小类别覆盖不足。
6. 没有真正应输出 `undetermined` 的样本。
7. 存在相同定理的多个版本，随机切分会产生数据泄漏。
8. 错误大多是人工构造的单一错误，与真实学生或模型错误仍有差距。
9. 全部集中在初等代数，不能支持跨领域泛化主张。

## 3. 具体样本修改建议

### 3.1 `m2-017`

当前证明已经比较完整：三个连续整数的和写成 `3n+3` 后，可以直接得到被 3 整除，因此更适合标为 `valid`，不适合作为遗漏桥接样本。

建议改为：

```text
1. 三个连续整数可以表示为 n,n+1,n+2。
2. 所以它们的和能被 3 整除。
```

预期缺失桥接：

```text
n+(n+1)+(n+2)=3(n+1)。
```

### 3.2 `m2-018`

“等式两边分别乘以 x 和 y”存在解释歧义。有人可能把它理解为结合 `x=y` 的合法代换，也可能理解为在等式两边乘不同的量。

建议明确错误操作：

```text
1. 在等式 x=y 的左边乘 x、右边乘 y，等式仍然成立。
2. 因此 x^2=y^2。
```

正确修复是两边同时平方，或者两边同乘一个量后再使用 `x=y` 代换。

### 3.3 `m2-020`

当前证明直接合法：已知 `x>0`，在 `x<1` 两边乘以正数 `x`，不等号方向保持不变。因此它应标为 `valid`。

若希望把它改成 gap 样本，可写为：

```text
1. 由 0<x<1，得到 x^2<x。
2. 结论成立。
```

预期最小桥接是：因为 `x>0`，用 `x` 乘 `x<1` 时不等号方向保持不变。

### 3.4 `m2-028`

原定理对整数成立，但“`n^2>=0`，所以 `n^2>=n`”不是合法推理。这是有价值的“真定理、错证明”样本。

建议将它明确归为 `invalid proof / repairable by replacement`，不要仅视为语言省略。推荐替换步骤：

```text
n^2-n=n(n-1)。
整数 n 与 n-1 是连续整数，因此 n(n-1)>=0。
所以 n^2>=n。
```

它可以专门测试模型是否区分“插入桥接”和“替换错误推理”。

### 3.5 `m2-030`

定理正确，但当前关于有理数集合成员关系的表述过于模糊，容易导致 A/B 标注分歧。

建议把错误写得更明确：

```text
1. x 不是有理数，而 r 是有理数。
2. 有理数集对加法封闭，所以 x+r 不是有理数。
```

正确修复应使用反证：若 `x+r` 是有理数，则 `x=(x+r)-r` 是有理数，与 `x` 无理矛盾。

### 3.6 `m2-035`

当前第 1 步写错不等号方向，第 2 步又自行纠正，适合测试模型是否坚持定位第一处错误，不因最终结论正确而忽略中间错误。

可以保留当前版本，并明确标记为“错误中间状态被正确结论掩盖”的专项样本。若要减少冗余，可以改成：

```text
1. 将 a<b 两边乘以 c，得到 ac<bc。
2. 因此 ac>bc。
```

### 3.7 `m2-037`

该题是清晰的循环论证，建议保留。它可以与 `m2-001`、`m2-040` 构成同定理对照组：

- `m2-001`：正确证明；
- `m2-037`：循环论证；
- `m2-040`：计算错误。

这三题必须放在同一数据划分中，不能将正确版本放入开发集、错误版本放入测试集。

### 3.8 `m2-041`

这是有价值的缺失假设样本，但 `c=0` 会使除法表达式未定义，因此不能作为普通真假反例登记。

两种保留方式：

1. 保留当前定理，预期诊断为 `missing_assumption: c!=0`；
2. 将定理改为包含 `c!=0`，然后在证明中偷偷忽略该前提，测试依赖恢复。

推荐保留第一种，以测试模型是否能区分“反例”和“未定义表达式”。

### 3.9 `m2-044`

当前 `(b+c)^2=b^2+bc+c^2` 很像简单输入笔误。若目标是基础算术审计，可以保留；若希望增加难度，建议改成更隐蔽的因式分解错误：

```text
(a+c)^2-(b+c)^2=(a-b)(a+b+c)。
```

正确结果应为：

```text
(a-b)(a+b+2c)。
```

### 3.10 `m2-045`

当前从 `b=ak` 得到 `b^2=a^2k` 的错误过于明显。可保留作低难度计算错误，也可升级为逆命题或整除条件误用样本。

若保留，最小修复是：

```text
b^2=a^2k^2。
```

并以整数 `k^2` 作为整除见证。

### 3.11 `m2-046`

当前 `|a+b|=sqrt(a^2+b^2)` 容易被熟悉三角不等式的模型直接识别。

建议增加表面合理性：

```text
1. |a+b|^2=(a+b)^2=a^2+b^2。
2. 所以 |a+b|=sqrt(a^2+b^2)<=|a|+|b|。
```

模型必须定位遗漏的交叉项 `2ab`，而不是只根据最终结论熟悉度判断。

### 3.12 `m2-049`

当前 `(p+r)/(qs)` 的错误较明显。建议改成更常见的学生错误：

```text
x+y=p/q+r/s=(ps+rq)/(q+s)。
```

正确修复是：

```text
x+y=(ps+rq)/(qs)。
```

这可以检验模型是否同时核查分子和分母。

## 4. 建议新增或替换的样本类型

### 4.1 `undetermined` 样本

当前 50 题没有真正证据不足的案例。建议至少加入 3 题：

```text
由前述引理可知 f 保持该性质，所以结论成立。
```

但题目没有提供“前述引理”的内容。系统应输出 `undetermined`，而不是猜测或接受。

还可以使用：

- 符号没有定义；
- OCR 损坏；
- 定理引用只有名称、没有准确陈述；
- 两种合理解释分别产生不同真假结果。

### 4.2 量词错误

建议加入至少 2–4 题：

```text
定理：对每个 x，存在 y 使 P(x,y)。
证明：存在 y，使对每个 x 都有 P(x,y)。
```

目标是测试模型能否发现 `forall x exists y` 被错误交换成 `exists y forall x`。

### 4.3 目标漂移

例如原目标是证明 `x=y`，证明最后只得到 `x^2=y^2`。模型应指出证明了更弱或不同的命题，而不是因为推导本身成立就接受原目标。

### 4.4 复杂依赖图

多数现有样本只是线性链。建议至少加入 5 题包含以下结构：

```text
n1 ----> n3
n2 ----> n3 ----> n5
n1 ------------> n4 ----> n5
```

应覆盖：

- 多父节点；
- 非相邻依赖；
- 两条独立分支；
- 错误节点只影响部分后代；
- 修复后只重验受影响后代。

### 4.5 无关但正确的步骤

加入数学上正确、但对目标没有支持作用的节点：

```text
1. n 是偶数。
2. 所以 n^2 是偶数。
3. 每个素数都有两个正因数。
4. 因此 n^2+n 是偶数。
```

第 3 步本身可能正确，但不能支持第 4 步。该类型可以检验模型是否把“事实正确”误认为“依赖有效”。

### 4.6 局部假命题但原定理正确

增加中间节点为假、但原定理仍可通过另一条路径证明的样本。系统应输出 `false_local_claim`，而不是误判为 `false_theorem`。

### 4.7 多步桥接

增加需要 2–3 个原子步骤才能补全的证明缺口，并要求每个桥接步骤都具有明确依赖和规则。避免所有 gap 都只是补一行代数化简。

### 4.8 真实错误样本

在后续版本加入学生或模型自然生成的证明。真实样本可能同时包含多个问题、模糊表达和后续错误，更适合测试第一处错误策略及 `undetermined` 校准。

## 5. 推荐的 50 题组成

若总数仍保持 50，推荐调整为：

| 类型 | 建议数量 |
|---|---:|
| 完整正确证明 | 8 |
| 真正的局部缺口 | 8 |
| 真定理、错证明 | 12 |
| 错误定理、有核验反例 | 8 |
| 缺失假设或定理误用 | 5 |
| 量词错误或目标漂移 | 4 |
| 应输出 `undetermined` | 3 |
| 复杂依赖与撤销专项 | 2 |

以上类别可以交叉，例如一个复杂依赖样本也可以包含局部假命题，但发布清单必须明确主类别与次级标签。

## 6. 难度分层建议

为避免强模型迅速饱和，建议为每个样本增加不作为模型输入的难度金标：

- `easy`：一步定义、简单反例、明显计算错误；
- `medium`：需要检查定理前提、两步桥接或非相邻依赖；
- `hard`：多分支依赖、隐蔽目标漂移、量词错误、多种合理解释；
- `abstention`：信息不足，正确行为是 `undetermined`。

主报告应分别给出各难度指标，不能只报告总体准确率。

## 7. 数据切分与防泄漏规则

1. 不能按单条样本随机切分。
2. 相同定理、同构定理和同一错误模板必须作为一个 `theorem_family` 分组。
3. `m2-001`、`m2-037`、`m2-040` 等同题变体必须进入同一 split。
4. 开发集使用过的错误模板不应仅替换变量后进入测试集。
5. 对照组应保留，但只用于同一 split 内的错误类型比较。
6. Prompt 调整不能查看保留测试集的错误答案或裁决结果。

建议新增元数据字段：

```json
{
  "theorem_family": "parity_sum_even",
  "error_template": "circular_reasoning",
  "difficulty": "medium",
  "source_kind": "synthetic_controlled",
  "split_group": "parity_sum_even_group"
}
```

## 8. 标注和验收改进

每题除当前标签外，建议增加：

- 原定理是否为真；
- 当前证明是否有效；
- 第一处 gap；
- 第一处 invalid；
- 失败推理边；
- 错误作用域：局部节点或原定理；
- 反例状态：有效、无效、不适用或未确定；
- 最小修复操作：insert、replace、delete、change theorem、irreparable；
- 修复是否改变原问题；
- 难度；
- 定理族和错误模板；
- 标注者置信度只作为分析信息，不能作为裁决依据。

A/B 分歧必须逐字段记录。Gold 只能来自双方一致值或包含证据与理由的共同裁决。

## 9. 指标建议

当前及修改后的样本应至少报告：

1. `validity_status` macro-F1；
2. 第一处错误精确匹配率；
3. 第一处错误相差一步的容忍匹配率；
4. 错误类型 macro-F1；
5. false acceptance rate；
6. 正确证明误拒率；
7. gap 被误判为 invalid 的比例；
8. invalid 被误判为 gap 的比例；
9. 反例发现率与反例有效率；
10. `undetermined` 的 precision、recall 和覆盖率；
11. 局部修复成功率；
12. 新错误引入率；
13. 后代失效和重验证正确率。

## 10. 推荐实施顺序

1. 冻结并保留 `m2-source-0.1` 及原始 A/B 标注。
2. 完成 Person A 标注、A/B 一致性报告和 v0.1 裁决。
3. 将本文列出的歧义样本优先修订为 `m2-source-0.2`。
4. 增加 `undetermined`、量词、目标漂移和复杂依赖样本。
5. 为所有样本补充定理族、错误模板、难度和来源类型。
6. 按定理族分组划分开发集与测试集。
7. 分别运行直接判断、自我反思、普通 Critic 和完整双 Agent 基线。
8. 根据错误分析扩充第二批真实学生或模型证明，而不是在保留测试集上调 Prompt。

## 11. 最终结论

当前 50 题作为 M2 pilot 是合格且实用的，尤其适合调通基础自检、“真定理、错证明”、第一处错误定位和局部修复流程。修改重点不应只是增加更多同类算术错误，而应增加：

- 应当弃权的样本；
- 量词和目标错误；
- 多步桥接；
- 复杂依赖与选择性撤销；
- 无关但正确的事实；
- 真实学生或模型错误；
- 防止同题和模板泄漏的数据分组。

完成这些修改后，这批数据才能从“功能验证集”升级为能够区分强模型、支持依赖图消融并为论文实验提供可靠证据的 benchmark。
