# M5 人工校验 3：Pilot 成本、延迟、重试和失败率报告

> [!IMPORTANT]
> **本文件要求真人对照外部账单和未删减运行归档。** 机器只能重算已提供的数字，不能证明调用明细完整、价格真实或失败未被选择性删除。没有人工复算和签署时，不得发布真实成本或失败率结论。

## 目的与责任人

本项用于确认 M5 Pilot 的成本和可靠性指标可以从未删减的真实调用记录重新计算。Person B 负责生成报告，独立审核者负责抽查明细、公式、计价来源和聚合结果。

## 机器无法独立验证的事项（必须人工确认）

- 输入明细是否覆盖提供方账户中的全部真实调用；
- 是否存在未提交、被删除或在仓库外重跑的失败样本；
- 价格表、模型版本、币种、税费和汇率来源是否真实适用；
- 缓存、fixture、开发调试和付费 Pilot 是否被如实区分；
- 失败原因分类和指标分母是否符合预先冻结的研究协议；
- 外部账单与本地 token/调用记录是否相符；
- 人工审核时间是否被正确披露，而不是混入或遗漏于 API 成本。

机器可以重算已提供的数据，但不能证明提供的数据完整、来源真实或没有选择性报告，因此必须由人工对照外部账单和运行归档。

## 必需输入

- 全部真实模型调用明细，包括失败调用；
- 每次调用的模型版本、输入/输出 token、延迟、状态和错误类型；
- 每个样本的补丁轮次、review 结果、重验结果和终止原因；
- 缓存命中记录及是否产生真实费用；
- 运行日期对应的官方计价页面或冻结价格快照；
- 币种、税费处理和汇率来源（若发生换算）；
- Pilot 输入样本总数及排除规则。

## 数据完整性人工校验

- [ ] 调用 ID 唯一且连续性异常有解释；
- [ ] 成功、失败、超时和解析错误都在明细中；
- [ ] 失败运行没有从分母中删除；
- [ ] 重试被计为新调用，同时能追溯到原始 attempt；
- [ ] 缓存命中与真实 API 调用分开；
- [ ] fixture、开发调试和正式 Pilot 有不同 run ID；
- [ ] token 合计可由逐调用明细相加得到；
- [ ] 延迟单位一致，未把排队时间与模型时间混淆；
- [ ] 价格对应运行时实际模型版本和日期。

## 必须报告的指标

### 调用与成本

- 总模型调用数、成功调用数、失败调用数；
- 输入 token、输出 token 和总 token；
- 每题、每次成功修复和整个 Pilot 的成本；
- Generator 成本、Evaluator/Person A 重验成本和完整闭环成本；
- 缓存前后成本，但不得把缓存节省当作模型能力提升。

### 延迟与轮次

- 总延迟、均值、中位数、P90 和最大值；
- 每题修复轮数及其分布；
- 首次补丁接受率和重试后接受率；
- 等价循环及最大轮次终止数量。

### 失败率

分别报告 Schema 错误、超时、传输错误、模型拒绝、问题改变、数学复核拒绝、等价补丁、最大轮次、重验失败和 `mark_irreparable`。同一运行若有多个失败阶段，应说明主失败原因的确定规则。

## 人工复算抽查

审核者至少抽查五个样本，并包含一个成功、一个模型失败、一个重试、一个人工拒绝和一个 Controller 重验失败。对每个样本从调用明细手工复算 token、成本、轮次和最终分类，再与报告比较。

总体指标应再进行一次独立脚本复算；若脚本由报告作者编写，审核者至少检查公式或使用另一实现交叉验证。

## 报告中禁止的做法

- 只报告均值而隐藏长尾；
- 删除失败、超时或高成本样本；
- 使用当前价格回填过去运行但不披露；
- 将 fixture token 当成真实 token；
- 混合同一模型的不同版本；
- 将人工审核时间伪装成 API 延迟，或完全忽略人工成本范围。

## 完成判据

聚合报告能由冻结明细完全重算，抽查无漏报失败或错误计价，真实调用与 fixture/缓存明确分离，审核记录绑定运行清单和聚合代码摘要。完成后才可冻结 Pilot 的成本、延迟、重试和失败率结论。
