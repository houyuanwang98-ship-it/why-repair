# M6 人工证据 8：预注册、方法公平性与冻结签署

> [!IMPORTANT]
> Schema、哈希和测试只能证明候选协议字节一致，不能证明它在结果可见前完成、签署者身份真实，也不能判断不同方法获得的信息与预算是否具有科学可比性。

## 机器无法可靠验证

- Person A 是否在任何 Pilot、正式输出或聚合结果可见前冻结 RQ、主要假设、指标、分母、失败计分和分层分析；
- 签署人是否为真实且具备数学判断能力的 Person A / Person B / Controller 负责人；
- 各基线获得的题面、局部上下文、Gold、定理库、工具和历史状态是否公平，是否存在语义泄漏；
- token、调用次数、墙钟和重试相同是否足以形成能力可比，而非表面数值相同；
- 每个消融是否只改变预注册的目标机制，或是否连带改变提示、模型、工具、截断和评分器；
- 结果暴露后是否发生选择性改假设、换主要指标或调 Prompt。

## 需要人工检查

人工逐项审阅 `M06_person_a_preregistered_protocol.md`、九种方法配置、Controller Manifest 候选、Prompt/工具权限表和提交历史。Person A 判断数学信息与指标可比性；Person B 判断实现差异与预算执行；Controller 负责人核对冻结对象及失败口径。三方分别形成意见后再共同签署精确摘要。

## 建议检查步骤与证据

1. 在接触正式结果前导出协议、代码、数据、Prompt、模型、定理库、评分器、统计方案和预算的 SHA-256 清单。
2. 为九种方法制作逐字段差异表，列出输入、可见上下文、工具、角色模型、最大 token、调用、重试、墙钟、修复轮次和评分器。
3. Person A 对每一差异写明是否属于方法定义、必要耦合或不公平优势；特别检查 `no_graph` 与后代失效的耦合。
4. Person B 以最少两个固定样本检查运行时实际请求和配置，而不是只读声明文件。
5. 查阅提交时间、运行账本和结果目录时间线，记录最早结果暴露时间及冻结时间；无法证明时标为 `undetermined`，不得声称预注册。
6. 三方在同一摘要上签署，记录姓名/角色、日期、独立性与利益冲突声明；签名必须绑定精确文件摘要。
7. 任何冻结后变更建立新版本，说明原因、是否看过结果、影响假设以及是否需要将分析降为探索性。

最低证据：冻结清单、方法差异表、实际请求抽查、时间线、三方逐项意见、摘要绑定签名和变更日志。

## 通过判据

- 冻结先于结果暴露，证据链可审计；三方真实签署绑定同一精确版本。
- 所有主要/次要指标、零分母、失败、超时和多重比较规则均预先确定。
- 方法差异均有科学理由，预算及信息权限可比；消融没有未披露的配置外变化。
- 冻结后变化均版本化，受影响结论被重跑或明确降为探索性。

## 不通过判据

- 只有字符串 `signed`、自报布尔值、仓库作者名或哈希，没有可核实签署和时序证据。
- 看过结果后选择假设、指标、样本、Prompt 或预算，却仍称预注册分析。
- 某方法得到 Gold、参考修复、额外上下文、更多有效预算或更强工具而未披露。
- 消融同时改变多个非目标因素，仍把差异归因于单一组件。

## 边界情况与常见误判

- 相同 token 上限不一定公平：不同 API 的计数、工具调用和上下文开销可能不同，应同时报告实际消耗和能力差异。
- 预注册候选的 Git 时间不等于真实未揭盲；只能作为辅助证据。
- 修复配置错误可允许，但必须冻结修复前发现的证据并判断是否导致全量重跑。
- 异模型双角色是系统配置比较，不应写成纯架构因果消融。
