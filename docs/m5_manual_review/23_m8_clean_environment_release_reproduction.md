# M8 人工证据 16：发布候选的干净环境端到端复现

> [!IMPORTANT]
> M7 抽样复现验证主实验可回放；M8 还必须验证最终发布包本身在干净环境中可安装、可运行、可重建论文产物，并与论文提交版本精确绑定。二者对象不同，不能互相替代。

## 机器无法可靠验证

- release candidate 是否包含全部且仅包含所需文件；
- 新用户是否无需作者本机状态、隐藏缓存、未声明环境变量或口头帮助即可复现；
- 最终论文表图能否从归档中的原始结果重新生成；
- 发布命令、系统卡和故障说明是否对陌生复现者足够清晰；
- 外部模型或第三方服务限制是否被如实呈现；
- 最终论文、代码、数据、Prompt、Manifest 和归档标识是否属于同一版本。

## 需要人工检查

独立复现实验者只拿最终 release candidate 和面向用户的说明，在全新环境执行安装、测试、数据审计、确定性回放、表图重建及预定小规模模型实验；不得读取开发工作区。

## 建议检查步骤与证据

1. Controller 生成候选包、版本索引和 SHA-256 清单；独立人另行验证下载/解压后的字节。
2. 在全新 VM/容器或独立机器记录镜像、系统、硬件、依赖、网络和凭证配置；禁止挂载开发缓存或源码目录。
3. 严格按公开安装说明执行唯一复现入口，记录从零开始的全部操作、耗时和人工干预。
4. 运行完整测试和数据审计；从归档原始结果重建全部论文表格、图、样本量、分母、CI、失败率和成本表。
5. 回放预注册确定性案例与小规模模型样本，比较字节级结果或预定义容差。
6. 验证论文 PDF/源文件、发布包、Manifest、Prompt、模型/价格 snapshot、定理库和版本索引互相绑定。
7. 提交独立复现报告；修复说明或包后创建新候选并从头复验，不在原包上静默覆盖。

最低证据：候选包摘要、干净环境证明、逐命令日志、重建表图、差异/容差报告、问题单、复验报告和独立签署。

## 通过判据

- 全新环境仅依据公开材料完成安装、测试、回放和论文表图重建。
- 所有确定性产物匹配；非确定性/外部模型结果在预定义容差内或有明确漂移报告。
- 没有未声明文件、绝对路径、隐藏缓存或作者手工补数据。
- 最终论文与 release candidate 的所有核心对象精确绑定。

## 不通过判据

- 需要访问开发目录、作者账号内的未发布文件或临时修补命令。
- 只验证代码能启动，没有从原始结果重建论文产物。
- 复现失败后直接修改原候选且不提升版本、不保留失败记录。
- 表图来源于作者导出的最终图片/表，而非归档原始结果和冻结脚本。

## 边界情况与常见误判

- M7 已通过抽样复现仍不能跳过本项，因为发布包、依赖和论文可能随后改变。
- 私有 API 凭证不应打包；说明应让复现者安全提供自己的凭证并明确费用。
- 外部服务不可用可形成“受限通过”，但离线确定性部分仍应完整通过并披露限制。
- 容器内成功不自动证明跨平台；项目只需声明并验证承诺支持的平台。
