# M7 人工证据 13：主实验独立回放与复现

> [!IMPORTANT]
> 同一开发环境内的测试和回放不能证明他人能依据发布材料复现；哈希一致也不能证明安装说明完整、隐藏依赖不存在或外部模型仍可获得。

## 机器无法可靠验证

- 复现实验者是否独立于实现和原始运行；
- 环境是否真正干净，是否偷偷依赖本机缓存、未声明文件、凭证、服务或人工步骤；
- 文档是否足以让未参与项目的人安装、运行和解释结果；
- 外部模型版本漂移是否处于预先允许范围；
- 回放抽样是否覆盖成功、失败、重试、反例、修复和多层 DAG 路径；
- 主要趋势能否在合理随机扰动下重现。

## 需要人工检查

由未参与实现的复现实验者在新目录，最好在独立机器/容器中，仅使用候选发布包和公开说明执行确定性回放、预注册的小规模模型实验及聚合重建。

## 建议检查步骤与证据

1. 复现者记录硬件、操作系统、语言/依赖版本、网络与外部服务、开始时目录状态，并证明未复制开发缓存。
2. 仅按 README/唯一复现入口安装；所有额外询问、缺失步骤和手工修正逐项登记。
3. 验证输入、代码、Prompt、模型、定理库、评分器和 Manifest 摘要，随后执行确定性结果重建。
4. 按冻结 seed/抽样规则回放完整链，覆盖不同方法和终态；逐项核对 run ID、依赖指纹、原始输出、评分输入和聚合。
5. 对可获得的模型执行小规模重复，报告相同模型 snapshot 或漂移版本，按预注册容差比较指标与主要趋势。
6. 从原始结果独立重建表、置信区间、失败率和成本摘要，不使用作者已生成的最终表作为输入。
7. 复现者提交成功、偏差、阻塞、未声明依赖和建议；项目方修复后由复现者复验。

最低证据：独立性声明、环境清单、完整命令/日志、输入输出摘要、问题单、差异表、重建结果和复验签署。

## 通过判据

- 干净环境能仅依文档完成安装、确定性回放和聚合重建。
- 抽样链覆盖预定高风险状态，关键字节、状态与分母一致。
- 小规模模型结果在预先定义容差内重现主要趋势，或版本漂移造成的限制被准确量化。
- 所有必要手工步骤和外部依赖均已进入正式说明。

## 不通过判据

- 复现依赖作者本机绝对路径、缓存、私有文件或口头指导而未补文档。
- 只运行单元测试或读取现成聚合表，没有从原始结果重建。
- 选择最容易成功的案例，未按冻结抽样覆盖失败路径。
- 外部模型不同却宣称数值完全复现，或偏差超过容差仍标通过。

## 边界情况与常见误判

- “独立目录”弱于“独立机器”；若只能用同机，应披露共享系统依赖和缓存风险。
- API 模型不可固定时可通过确定性 fixture 加趋势级模型复现，但不能声称位级复现。
- 文档勘误后成功不抹去首次失败，二者都应保留。
- 无网络环境无法验证 provider 实验，但仍可验证离线聚合和确定性 Controller 回放。
