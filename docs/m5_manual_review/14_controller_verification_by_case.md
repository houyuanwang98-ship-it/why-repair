# Controller 人工验证包：按里程碑与案例分工

> [!IMPORTANT]
> 本文件只检查机械状态、版本、依赖、缓存和审计链。Controller 不能决定数学真值；人工审核者要确认代码没有把格式合法、模型自信或角色字符串当成数学正确。

## M0：A–J 的 Controller 行为

- **A–C**：只接收 Evaluator 裁决，不自行区分 accepted/gap。
- **D**：节点 2 修复后使所有依赖旧版本的后代 stale。
- **E**：候选反例未核验前不能进入 counterexample_found。
- **F**：节点 1 无效时节点 2 为 blocked_by_invalid_dependency，不新增数学错误。
- **G–H**：域或定理条件缺失时允许 undetermined/pending repair。
- **I**：切分错误返回表示层，不构造伪数学节点状态。
- **J**：外部证据缺失时保持非终态或 undetermined。

## M1：状态机逐对象验证

人工审查所有允许/禁止转换，重点验证：pending 不能直接 active；当前版本唯一；supersedes 链连续；未来边、跨 proof、自环、循环和陈旧补丁拒绝；事务失败完整回滚；Generator 与 Evaluator 身份不重合。

## M2：50 题数据治理

对 **m2-001–050 每一题** 检查 proof_id 唯一、节点 ID/依赖存在、Gold 与源摘要绑定、A/B 私有文件在比较前隔离、分歧有状态和裁决记录。Controller 只列出差异，不选择数学答案；缺来源或签名时标记证据门失败。

## M3：50 题模块与运行状态

对 **m2-001–050 每一题** 检查分阶段输入输出绑定：切分 → 分类 → 依赖图 → 节点裁决。上游错误不能静默算入下游；每题必须有成功结果或显式失败状态。缓存键含模型、Prompt、Schema、上下文和依赖摘要；历史非盲运行不得标 publication result。

## M4：11 个反例状态链

以下每个案例必须分别拥有自己的状态链，不得共用一条汇总结论：

- **m2-021**：偶数和逆命题反例状态链。
- **m2-022**：非零实数之和反例状态链。
- **m2-023**：四整除逆命题反例状态链。
- **m2-024**：所有素数为奇数反例状态链。
- **m2-025**：平方相等推出原值相等反例状态链。
- **m2-026**：偶乘积推出两因子都偶反例状态链。
- **m2-027**：正数倒数不等号方向反例状态链。
- **m2-029**：和为零推出各自为零反例状态链。
- **m2-042**：实数平方保序反例状态链。
- **m2-043**：一般整数版本欧几里得引理反例状态链。
- **m2-048**：零乘积中“或/且”混淆反例状态链。

每条链均验证：candidate → pending verification → Person B 执行记录 → Person A review → accepted/rejected/undetermined。任何前提未真、目标未假、语义未批准或外部签名缺失，都不能由 Controller 越权改成严格研究通过。

## M5：50 题补丁闭环

对 **m2-001–050 每一题** 根据适用性检查：

- 无错误/不可修题有明确跳过或 irreparable 原因；
- 补丁绑定当前 ErrorCertificate 和目标版本；
- replace、insert、delete 创建正确版本历史；
- 修改目标后完整后代闭包 stale 并清缓存；
- PatchReview 通过不等于修复成功；
- 新目标和重建后代按拓扑顺序由受信 Evaluator 重验；
- rejected/undetermined 失败闭合；
- 异常原子回滚；等价补丁或最大轮次终止；
- 运行清单保留成功、失败、token、延迟和最终摘要。

## 外部人工代码审查

未参与实现的 reviewer 应逐项攻击角色伪造、版本重放、依赖重定向、删除拼接、缓存碰撞、乱序重验、重复 evaluation ID、部分回滚和指标漏计。每个 finding 绑定文件行、严重度、修复提交和复验结论。

## 签署

记录 reviewer 独立性、审查提交 SHA、覆盖案例、测试命令、findings、未覆盖范围、决定、时间和签名。没有外部签名时只能称自动化 Controller 回归通过。
