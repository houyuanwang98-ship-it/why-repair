# M8 人工证据 17：发布许可、隐私、系统卡与材料完整性审查

> [!IMPORTANT]
> 密钥正则、文件清单和自动许可证扫描不能判断授权条款是否覆盖再发布、组合数据能否重新识别个人、系统卡是否充分披露风险，或发布材料是否满足研究与伦理责任。

## 机器无法可靠验证

- 数据、题目、论文摘录、模型输出、代码和第三方依赖的许可证是否兼容目标发布方式；
- 个人信息、学生答案、批注和来源元数据是否已充分去标识化，组合后是否仍可识别；
- 模型/provider 条款是否允许保存、分析和再分发输出；
- 系统卡是否真实、完整地描述用途、非目标、失败模式、人工复核、成本和隐私风险；
- 自动扫描未发现的语义秘密、内部 URL、历史凭证和未授权文件；
- release notes、数据卡、引用、许可证和归档元数据是否完整一致。

## 需要人工检查

由数据负责人、Person B 和具备许可/隐私判断能力的独立 reviewer 对最终发布候选逐文件审查；高风险或不明确条款应提交机构法务/伦理渠道，而非由项目代码自行裁决。

## 建议检查步骤与证据

1. 建立物料清单：每个数据/代码/模型/依赖/文档对象的来源、作者、版本、许可证、修改、分发方式和证明链接/文件。
2. 对教材、题库、论文、学生答案和模型输出逐项判断研究使用、引用、修改与再分发权；不确定项先排除或取得书面许可。
3. 人工检查内容和元数据中的姓名、学校、学号、评分、批注、路径、用户名、内部服务、请求 ID 和可链接组合字段。
4. 结合自动扫描与 Git 历史审查密钥、token、私钥、内部 URL 和已删除敏感文件；发现泄露立即轮换凭证并评估历史清理。
5. 审阅数据卡和系统卡是否覆盖来源比例、目标用户、自然语言审计边界、`undetermined`、错误接受/错误修复、人工监督、领域/模型限制、成本和隐私。
6. 核对第三方 NOTICE、引用、许可证文本、模型/价格 snapshot、release notes、已知问题和归档标识。
7. 独立 reviewer 逐项签署；任何材料变化均重新生成清单并复核受影响项。

最低证据：物料/许可证清单、书面许可、隐私复核表、秘密与历史扫描报告、数据卡、系统卡、NOTICE、凭证处置记录和独立签署。

## 通过判据

- 所有发布对象均有明确且相容的授权依据；不明确或禁止分发的对象未进入包。
- 无个人信息、有效密钥、内部敏感标识或不可追踪文件；高风险历史问题已处置。
- 数据卡和系统卡准确覆盖用途、限制、失败、人工复核、成本、隐私和模型版本风险。
- 发布包、论文与归档元数据中的许可证、引用和版本一致。

## 不通过判据

- 以“网上公开”“仅研究用途”或自动扫描通过替代逐项权利判断。
- 仍含学生身份、评分批注、作者本机路径、有效凭证或内部 URL。
- 系统卡只描述功能，不披露错误接受、false repair、弃权和人工复核需求。
- 依赖、数据或模型输出没有可追踪来源/条款，却计划公开分发。

## 边界情况与常见误判

- 去掉姓名不一定匿名；来源、题目、时间和自由文本组合可能重新识别个人。
- 开源代码许可证不自动覆盖数据、模型权重或模型输出。
- 秘密已失效仍应从发布包移除并记录处置；Git 历史是否重写需结合已发布范围和协作风险决定。
- 本文件是发布治理检查，不构成法律意见；条款不明确时应升级给有权限的专业人员。
