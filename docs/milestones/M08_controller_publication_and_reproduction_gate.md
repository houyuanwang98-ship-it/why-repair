# M8 Controller：论文数字、发布清单与复现门

状态：`person_a_cross_review_needs_revision_fail_closed`

版本：`m8-controller-0.1`

日期：2026-08-15

对应任务：`docs/m0_m8_research_execution_sequence.md` §13.3 第 1–7 项

## 1. 职责与当前结论

M8 Controller 只机械核对论文输出、文件字节、运行证据和发布门，不判断数学正确性，也不能替代外部审查。当前实现是候选门骨架：可重建一张终态计数/资源汇总表、绑定文件字节并扫描少量文本密钥模式，但尚未实现论文全部指标/置信区间/图表生成、版本索引、复现命令执行、完整数据/隐私/许可证审计或可信外部证明验证。M5–M7 正式退出、正式原始结果、外部审查和干净环境复现都不存在，因此 `release_allowed=false`。

## 2. 七项自动化顺序

1. 表格与图表只能由精确预分配集合和逐运行终态账本重建；成功数与失败数必须等于预分配分母，不能拿预聚合行冒充原始结果重建。
2. 论文数字必须与重建产物逐字段一致；当前没有正式结果，所以不得生成占位数字冒充论文结果。
3. 代码、数据、Prompt、模型、定理库、Schema、评分器和环境须以规范化仓库相对路径及 SHA-256 绑定。
4. 复现命令、文件哈希和发布清单须形成同一个不可变候选身份。
5. 完整测试、数据审计、隐私与许可证审查都必须有独立证据。自动密钥模式扫描只是一项负向检查，不证明隐私或许可已经通过。
6. 干净环境确定性复现和小规模模型实验必须保存环境、命令、退出码、输出摘要和外部限制；当前未执行。
7. 每一个真门都必须绑定至少一个仍匹配实际字节的证据文件。但文件哈希不能认证审核者身份或证明文件内容真实。v0.1 没有可信证明验证器，故新增不可由调用者设置的 `trusted_attestations_verified=false`；即使调用者把其余布尔门设真并附任意文件，仍不得生成 `release_ready`。未来开放发布必须提升协议版本并实现可信证明校验。

## 3. 实现与机器证据

`harness/m8_controller.py` 实现规范化文件冻结、上游实际字节复核、原始终态账本聚合、汇总表分母检查、逐门证据绑定、保守密钥扫描、候选构建和重建验证。候选本身保存冻结的预分配集合与逐运行终态账本，因此可脱离进程内临时状态重算当前汇总表。`tests/test_m8_controller.py` 覆盖当前候选、漏计分母、失败运行保留、陈旧摘要、路径逃逸、密钥 finding，以及“任意布尔值与任意证据文件不得打开发布门”。机器候选位于 `data/benchmarks/m8/controller_publication_candidate_v0_1.json`。

当前候选不含正式论文表格；空表是“正式结果不存在”的显式表达，不是零结果。自动扫描也不读取凭证库、Git 历史、二进制语义、数据授权或个人身份，发布前仍需专门工具和真人复核。

## 4. 退出决定

M8 Controller §13.3 当前为 `needs_revision`：文件冻结、上游复核、基础汇总表、分母门、保守扫描和不可伪造为 release 的候选契约通过；完整表图生成、数字/置信区间核对、版本索引、复现命令执行、完整测试/数据/隐私/许可审计与论文提交绑定尚未实现。正式 M8 退出还被 M5–M7、Person A 第 1、3–7 项、正式结果/成本、第三方数学审查、外部代码审查、独立复现和系统卡阻塞；不得创建 release、tag、DOI 或论文最终数字。
