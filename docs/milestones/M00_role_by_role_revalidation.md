# M0 逐角色复核与验收记录

版本：`m0-role-revalidation-v1.1`

复核日期：`2026-08-14`

复核范围：仅 M0 的 Person A、Person B、Evaluator Agent、Repair Generator Agent 与 Controller。M1–M4 的实现正确性不在本记录中重复验收。

依据：

- `docs/m0_m8_research_execution_sequence.md` 第 5 节；
- `docs/project_validation_and_acceptance_plan.md` 第 2 节、第 26 节以及第 35–37 节；
- M0 原始范围契约、A/B 原始评审、共同裁决和完整性限制说明。

## 总结论

M0 的术语与权限边界可继续作为 M1–M4 的工程基线，但 M0 的“严格双盲独立标注”验收门未获得可追溯证据。该缺口不能通过事后编辑原始评审修复。若论文需要把双人独立一致性作为研究证据，必须由两名未接触既有答案的审阅者在隔离环境重新标注并发布新版本。

原始 A/B 答案不作回写；共同裁决继续作为当前工程语义。`M00_scope_and_terminology.md` 中“已完成独立评审”和“退出条件已满足”的历史表述，应与 `M00_integrity_limitation.md` 一起阅读，后者是当前有效的证据限定。

机器可读记录位于 `data/benchmarks/m0_role_revalidation_v1.json`，由 `schemas/m0_role_revalidation_v1.schema.json` 约束。每个正式记录均包含验收计划第 1.4 节要求的十个字段。此次仓库自检没有新的独立人类签名；相应记录明确写作 `unassigned_independent_human_reviewer`，不得误读为已经完成外部复核。

## 1. Person A

结果：`needs_revision`（研究证据），`pass`（裁决后的工程语义）。

- 已覆盖目标、非目标、核心对象、数学裁决、错误类型、反例、修复成功、最小修复、研究问题与指标。
- 已留下 10 个边界案例的原始回答，没有用最终裁决覆盖。
- 原始回答存在未完成项和非契约表达：案例 J及审阅清单第 1、7 项未作答；案例 C 使用“一个节点以内”的不稳定标准；案例 E/F 混用了错误类型与依赖状态；部分标签使用中文自由文本。
- 上述语义问题已由 `M00_adjudication.md` 书面裁决，当前工程契约不再采用被否决规则。
- 不能证明该回答是在不可见 Person B 答案的隔离条件下完成。

处置：保留原始文件；不把它单独称为合格的独立标注。需要严格研究证据时重新盲标。

## 2. Person B

结果：`pass_with_limitation`。

- 逐案给出了节点类型、依赖、裁决、错误类型/范围和执行语义，并回答全部七项审阅问题。
- 明确区分数学裁决、诊断错误、反例范围与生命周期状态。
- 明确 Controller 可机械检查的条件，以及必须交给 Evaluator 的数学判断。
- 明确列出非正式枚举、模糊定义、版本绑定、失效传播和独立补丁复核风险。
- 文件主动披露接手时已看到既有 A 与裁决内容，因此不能作为严格盲审证据。

处置：接受为执行语义复核和工程交接证据；拒绝将其用于双盲一致性主张。

## 3. Evaluator Agent

结果：`pass`（M0 权限契约）。

- 输入边界限定为题目、证明、合法上下文和已验证证据。
- 权限包含切分、分类、建图、局部义务裁决、诊断、候选反例与独立补丁复核。
- 禁止在验证模式静默修改证明、使用后续节点、以检索相似度或“未找到反例”作为接受证据。
- 数学裁决集合不包含 `stale` 或 `blocked_by_invalid_dependency`；后者明确属于 Controller 生命周期。
- M0 不要求实现或模型行为测试，实际分阶段 Evaluator 验证属于 M3。

处置：M0 无需代码修改。

## 4. Repair Generator Agent

结果：`pass`（M0 权限契约）。

- 只允许依据 Error Certificate 和获准局部上下文提出受预算约束的局部补丁，或报告不可修复。
- 禁止自行接受补丁、静默改变题目/假设/定义域、使用隐藏上下文及重写无关分支。
- 修复成功要求独立 Evaluator 复核、失败边得到解决、后代重验且原问题保持不变。
- M0 只冻结权限与术语；模型生成、操作预算和事务应用的实现验收属于 M5，不能提前宣称完成。

处置：M0 无需代码修改；跨阶段审计继续保留“模型驱动 Repair Generator 属于 M5”的限制。

## 5. Controller

结果：`pass`（M0 权限边界），`not_applicable`（完整实现）。

- 可执行职责限定为 Schema、状态、版本、DAG、缓存、重试、撤销、调用和审计记录。
- 禁止创造数学裁决，禁止把 JSON 合法、缓存命中或模型一致当成数学正确。
- 当前术语明确区分 `mathematical_verdict`、`error_type`、反例 `scope` 和 `lifecycle_state`。
- 版本变化必须使依赖旧版本的后代裁决 stale，并按拓扑序重验；这些是后续 Controller 实现的强制不变量。
- 验收计划明确 M0 不要求完整 Controller，因此跨阶段审计中的 `M0.controller=false` 表示“不在本阶段实现”，不是权限边界失败。

处置：权限边界通过；完整实现由 M1 及后续阶段验证。
