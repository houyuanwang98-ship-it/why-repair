# M7 正式实验预注册协议 v0.2

状态：`protocol_locked_formal_run_blocked`。本协议在任何新外部正式测试集结果可见前锁定。它不把已经公开并参与工程审查的 OPC-250 重新包装为盲态测试集。

## 数据角色

- OPC-250 v0.2：仅用于开发、流程验证、错误分类和探索性结果；不得支持确认性泛化主张。
- 新 pilot：20–50 个独立样本，用于验证采集、标注、运行和计分流程；使用后不得进入正式测试集。
- 新正式测试集：来源独立、许可可审计、在冻结前不用于调参；样本 ID、原始字节、来源提交、许可、排除原因和 split 均写入只读清单。

## 研究问题与主要端点

沿用 M6 v0.1 的 RQ1–RQ3。确认性主要端点为首错精确率、无首错假阳性率、false-accept rate、有效反例覆盖率、verified repair success、false-repair rate 和 new-error introduction rate。不得看到结果后更换主要端点。

## 方法与预算

正式比较限定为完整系统、整篇直接判断、自我反思、Generator–Critic，以及分别移除图、结构化证书、反例协议、后代撤销和多轮修复的预定义消融。每样本模型、prompt、token、调用次数、超时、重试、工具权限和上下文截断必须在运行清单中冻结；基础设施失败进入 intention-to-treat 分母。

## Gold 与人工审查

每个正式样本必须由两名审核者独立标注 proof verdict、首错、错误类型、反例范围和 repairability。双方先锁定摘要再交换结果；分歧由第三名数学专家裁决。任何参与方法开发的人不得作为正式测试集唯一 Gold 审核者。

## 统计与样本量

在 pilot 结果冻结后，使用 pilot 估计的基线率和保守效应阈值完成配对样本量/功效计算。确认性比较使用配对 bootstrap 95% CI、配对随机化检验和按 RQ 划分的 Holm 校正。功效不足时只报告估计和区间，不作“无差异”结论。

## 冻结与揭盲

正式运行前冻结数据、Gold、代码、prompt、模型、工具、预算、统计环境和随机 seed 的摘要。测试集 Gold、参考修复和方法身份在逐例审查完成前保持隔离。所有失败、重试和原始响应均保留；变更只能发布新协议版本。
